目的

- リポジトリ直下に `仕様書.md` を作成し、現行コードと既存要件の関係を一望できる正本を置く。
- MCPサーバー、データ取得、検索、本文整形、ライセンス、セキュリティ、運用、検証の仕様を構造化して固定する。
- 今後の実装・PRが参照できる粒度で、入力、出力、エラー、制限、受入基準を明文化する。

非目的

- コード挙動の変更
- MCP tool / resource / prompt の追加・削除・改名
- 外部API、依存関係、ビルド設定、テストの変更
- `dist/` や生成物の手編集

受入基準

- `仕様書.md` がリポジトリ直下に存在する。
- `仕様書.md` が以下を含む。
  - プロジェクト概要、対象範囲、非対象範囲
  - ディレクトリ構成と責務
  - MCP transport、tools、resources、prompts
  - データ取得、キャッシュ、検索、本文整形、関連抽出、ライセンス
  - セキュリティ、監査ログ、レート制限、エラー形式
  - 環境変数、起動方法、検証コマンド、受入基準
  - 現行の制限と未確定点
- コード変更がないため、検証はフォーマット確認と既存テストを中心に行う。

検証コマンド

- `npm test`
- `npm run build`
- `npm run lint`
- `npm run format:check`

リスク/注意点

- `docs/要件定義.md` は要求、`仕様書.md` は現行仕様として位置づける。両者がずれる場合は、現行コードで確認できる挙動を `仕様書.md` に書き、要求との差は制限・未確定点として残す。
- MCP toolの戻り値は外部利用者に影響するため、フィールド名、エラー文、入力制約を曖昧にしない。
- SCP Wiki由来コンテンツのライセンス表記、非公式であること、本文が非信頼データであることを省略しない。
